# Method Sources

This file maps the exact upstream sources used by the History Book project.

These links are **method/reference sources**, not History Book authority. The project-specific application is owned by [BOOK_BUILD_SYSTEM.md](BOOK_BUILD_SYSTEM.md) and the repository contract in [../AGENTS.md](../AGENTS.md).

## MAPS_L — project shaping, evidence, task quality, review

### [Project Bootstrap](https://github.com/BigCatMellow/MAPS_Lean/blob/main/playbook/PROJECT_BOOTSTRAP.md)

Borrow:

- inspect current reality before planning;
- define observable DONE and final proof;
- plan backward from the outcome;
- challenge assumptions before launch;
- adapt from evidence;
- stop only when proof passes or a real boundary blocks progress.

History Book use:

- defines the parent book outcome;
- defines chapter/section completion;
- prevents outlining from becoming a substitute for verified work.

### [Operator Request Compilation](https://github.com/BigCatMellow/MAPS_Lean/blob/main/playbook/REQUEST_COMPILATION.md)

Borrow:

- compile a human request into a durable bounded execution contract;
- preserve intent;
- define source of truth, boundary, dependencies, acceptance, verification, and recovery.

History Book use:

- turns a topic such as “write Reconstruction” into a section contract a fresh researcher/writer can execute.

### [Agent-Grade Instructions Standard](https://github.com/BigCatMellow/MAPS_Lean/blob/main/playbook/AGI_STANDARD.md)

Borrow:

- observable outcome;
- authoritative inputs;
- explicit work boundary;
- acceptance criteria;
- verification;
- failure/recovery;
- fresh-agent and no-guess tests.

History Book use:

- makes each consequential section executable without relying on hidden chat context.

### [Research Before Architecture](https://github.com/BigCatMellow/MAPS_Lean/blob/main/playbook/RESEARCH.md)

Borrow:

```text
Question
→ brief
→ sources
→ evaluate
→ claims/evidence
→ assumptions
→ summary
→ decision/task
```

Also borrow:

- primary sources first where practical;
- precise source locators;
- mark assumptions;
- preserve disagreement;
- never average or guess across conflicting sources.

History Book use:

- core claim-evidence workflow.

### [Checks and Balances](https://github.com/BigCatMellow/MAPS_Lean/blob/main/docs/CHECKS_AND_BALANCES.md)

Borrow:

- risk-proportional verification;
- independent review for consequential work;
- evidence sufficient for another reviewer to reproduce the claim;
- concrete blocking findings rather than preference-based review.

History Book use:

- low/medium/high review levels for factual passages, causal synthesis, and disputed/load-bearing interpretations.

### [Tenth Seat Review](https://github.com/BigCatMellow/MAPS_Lean/blob/main/playbook/TENTH_SEAT_REVIEW.md)

Borrow cautiously:

- when a consequential conclusion has escaped meaningful challenge, construct the strongest plausible alternative;
- identify assumptions;
- identify the weakest assumption;
- state evidence expected under the alternative;
- look for that evidence;
- record evidence against the alternative too;
- preserve reopening indicators.

Boundary:

The upstream file's triggers are MAPS_L repository/PR-specific. They do **not** automatically govern History Book sections. The History Book may use a project-specific adversarial-challenge analogue as described in [BOOK_BUILD_SYSTEM.md](BOOK_BUILD_SYSTEM.md).

# Rung Teaching — how the reader learns

### [Rung README](https://github.com/BigCatMellow/Rung_Teaching/blob/main/README.md)

Core principle:

The learner should increasingly become capable of doing the reasoning without the teacher.

History Book use:

- readers should leave able to evaluate historical claims, not merely repeat the book's wording.

### [Teaching Loop](https://github.com/BigCatMellow/Rung_Teaching/blob/main/wiki/Teaching-Loop.md)

Borrow:

```text
ORIENT
→ ATTEMPT
→ DIAGNOSE
→ EXPLAIN
→ MINIMUM HELP
→ REATTEMPT
→ VERIFY
→ TRANSFER
```

History Book use:

- begin with an understandable question/model;
- expose where the simple model breaks;
- explain the missing concept;
- let the reader apply the concept to a different case.

### [Assistance Ladder](https://github.com/BigCatMellow/Rung_Teaching/blob/main/wiki/Assistance-Ladder.md)

Borrow:

- least help that restores productive progress;
- direct explanation when prerequisite knowledge is genuinely missing;
- avoid both over-helping and unsupported guessing.

History Book use:

- explain historical vocabulary/context when needed, but do not front-load every caveat before the reader has a usable model.

### [Diagnosing Mistakes](https://github.com/BigCatMellow/Rung_Teaching/blob/main/wiki/Diagnosing-Mistakes.md)

Borrow:

- distinguish missing facts, misconceptions, strategy errors, judgment errors, and monitoring errors.

History Book use:

- identify what kind of misunderstanding a common historical myth actually represents before correcting it.

### [Mastery and Transfer](https://github.com/BigCatMellow/Rung_Teaching/blob/main/wiki/Mastery-and-Transfer.md)

Borrow:

> Assisted success is not mastery.

History Book use:

- major sections end with a fresh case or claim that requires the same reasoning under different surface details.

### [Research Foundations](https://github.com/BigCatMellow/Rung_Teaching/blob/main/wiki/Research-Foundations.md)

Borrow:

- retrieval practice;
- self-explanation;
- cognitive-load awareness;
- worked examples;
- productive failure used proportionally.

History Book use:

- educational design should be evidence-aware rather than based only on intuition.

# THINK — historical framing and alternative explanations

### [THINK Project](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-creativity-and-ideation/THINK_PROJECT.md)

Current evidence-backed baseline emphasized by the project:

- decomposition;
- assumption mapping;
- first principles;
- counterexample search.

History Book use:

- frame hard historical questions before researching them;
- expose assumptions;
- generate serious alternative explanations;
- identify evidence that would discriminate among them.

Important boundary:

THINK's richer search / Idea Ecology mechanisms are not assumed to be default-good merely because they exist in research. The History Book likewise uses the smallest reasoning depth that materially improves the historical question.

### [THINK Evidence-Driven Improvement Roadmap](https://github.com/BigCatMellow/Pilot_Projects/blob/main/complete-ai-work-system/roadmaps/03-THINK-CREATIVITY-AND-IDEA-ECOLOGY.md)

Borrow:

- additional thinking must justify its cost;
- escalation is conditional;
- a simple structured path is the default comparator;
- uncertainty or failure signals should determine whether extra reasoning is warranted.

History Book use:

- routine factual material stays routine;
- disputed/load-bearing questions receive deeper framing and counterexample search.

### [THINK Roadmap Map](https://github.com/BigCatMellow/Pilot_Projects/blob/main/complete-ai-work-system/roadmaps/think/README.md)

Useful research areas:

- cognitive methods;
- meta-control and search;
- idea ecology and memory;
- evaluation and benchmarks;
- method learning;
- conversation/branching architecture.

History Book use:

- reference when the project needs deeper reasoning architecture, but do not import complexity by default.

# PLAN — turn explanations into bounded investigations

### [AI Planning and Orchestration Research](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-planning-and-orchestration/README.md)

Borrow:

- planning should deepen only when evidence shows a need;
- diagnosis-gated decomposition;
- expected evidence / discrepancy;
- smallest-correction reconciliation;
- value-of-information thinking;
- distinguish useful/plausible from executable/grounded.

History Book use:

- determine which evidence actually matters;
- research the smallest evidence package capable of changing the conclusion;
- do not research indiscriminately.

### [PLAN Orchestration and Task Compilation Roadmap](https://github.com/BigCatMellow/Pilot_Projects/blob/main/complete-ai-work-system/roadmaps/05-PLAN-ORCHESTRATION-AND-TASK-COMPILATION.md)

Borrow:

- preserve the reasoning/uncertainty that produced the plan;
- do not flatten meaningful alternatives into a task list;
- expected evidence can route whether to continue, research, revise the plan, or return to THINK.

History Book use:

- a research task should retain the historical hypothesis it is testing and what evidence would change the interpretation.

### [PLAN Roadmap Map](https://github.com/BigCatMellow/Pilot_Projects/blob/main/complete-ai-work-system/roadmaps/plan/README.md)

Useful questions for this project:

- when should extra planning activate?
- when should information be acquired instead of writing?
- when does a new observation require local correction vs replanning?
- when is richer dependency/contingency structure actually needed?

# AI Design Bible — make the history legible

### [AI Design Bible](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/README.md)

Borrow:

- product/task truth before visual treatment;
- routed use of the smallest relevant guidance;
- evaluation rather than assuming design quality.

History Book use:

- content structure precedes decoration.

### [Foundations](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/FOUNDATIONS.md)

Borrow:

- chunking;
- hierarchy;
- stable placement;
- consistent labels;
- progressive disclosure;
- remove irrelevant information without removing necessary context.

History Book use:

- build layered pages/sections that support both skimming and deep reading.

### [Interaction and Information Design](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/INTERACTION-AND-INFORMATION.md)

Borrow:

- prominence should follow consequence/frequency;
- classify information by importance;
- use tables when comparison is genuinely tabular;
- preserve context when compressing information.

History Book use:

- timelines, comparisons, sidebars, and evidence tables should clarify relationships rather than decorate.

### [Visual Systems](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/VISUAL-SYSTEMS.md)

Borrow:

- visual hierarchy must reflect information hierarchy;
- typography communicates structure;
- constrain long-form line length;
- density is a deliberate decision.

History Book use:

- distinguish main narrative, context, evidence, myth/memory, and modern connection visually without making every element compete for attention.

### [Evaluation](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/EVALUATION.md)

Borrow:

- one attractive output is not proof;
- creation and evaluation should be separated;
- use fresh/separate judgment for consequential work.

History Book use:

- prototype representative pages/sections and test whether the design actually improves comprehension.

### [Anti-Patterns](https://github.com/BigCatMellow/Pilot_Projects/blob/main/ai-design-bible/ANTI-PATTERNS.md)

Borrow:

- avoid card soup / excessive decoration;
- avoid fake minimalism;
- do not repair weak hierarchy with gradients/icons/shadows;
- do not fabricate content to fill space.

History Book use:

- the book should feel designed because relationships are clear, not because every paragraph is wrapped in a visual gimmick.
